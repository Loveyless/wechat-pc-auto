# Plan: 翻译与TTS配置收敛及JSON扩展设计

## 背景与动机
当前桌面壳已经落地安全的 `GET /api/config` / `PUT /api/config` 与 provider-specific TTS 表单，但 translate 仍停留在“顶层 `deeplx_url` 特例”，TTS 路由仍依赖单一 `tts.config_path`，这两个契约对 provider 扩展并不对称：`listener_app/runtime_config_store.py:108`、`listener_app/runtime_config_store.py:116`、`listener_app/runtime_config_store.py:242`、`listener_app/runtime_config_store.py:262`、`listener_app/runtime_config_store.py:283`。当前活跃 OpenSpec change 已经把“安全 DTO + settings 工作区 + 按文件边界持久化”定义成既有能力，本需求本质上是收敛这套能力的 translate/TTS 配置边界，而不是再开第二套配置系统：`openspec/changes/add-desktop-config-gui-and-apply-flow/proposal.md:8`、`openspec/changes/add-desktop-config-gui-and-apply-flow/specs/desktop-runtime-config-api/spec.md:3`、`openspec/changes/add-desktop-config-gui-and-apply-flow/specs/desktop-shell-settings/spec.md:3`。
<!-- 下游：proposal.md 的 motivation -->

## Goal
- 把 translate 配置改成 provider-aware 契约：保留 shared 字段，新增 `translate.providers.<provider>` 分支，消除顶层 `translate.deeplx_url` 特例。
- 把 TTS 主配置改成“provider 选择 + 每个 provider 的 `config_path` 索引”，不再让单一 `tts.config_path` 随 active provider 漂移语义。
- 让 `/api/config` 与桌面壳设置页围绕核心 translate/TTS 配置工作，同时继续遵守 write-only secret、未知字段保留、原子写入和 runtime toggle 分离。
<!-- 下游：proposal.md 的 scope -->

## Non-goals
- 不新增 `.env.local` GUI 编辑能力；secret 仍只通过 direct/env/clear 形式写入配置元数据。
- 不把 TTS provider 私有参数重新塞回 `listener.json`，也不强行把不同厂商字段捏成一套“大一统” schema。
- 不做 translator / TTS player 的进程内热重载；保存后是否生效仍遵守现有 save/apply 语义。
- 不要求第一阶段把所有云 TTS 的高级调参都暴露到设置页首屏。
<!-- 下游：proposal.md 的 scope -->

## 当前仓库事实
- `runtime_config.py` 仍把 translate 运行时建模为 shared 字段加单个 `deeplx_url`，TTS 运行时则建模为 `provider + raw_config + config_path`；启动加载阶段也是按这两个旧结构解析：`listener_app/runtime_config.py:64`、`listener_app/runtime_config.py:81`、`listener_app/runtime_config.py:158`、`listener_app/runtime_config.py:160`、`listener_app/runtime_config.py:174`。
- 当前 translate provider 只支持 `deeplx` 和 `passthrough`，校验逻辑只会在 `provider=deeplx` 时要求 `translate.deeplx_url` 或 `translate.deeplx_url_env`：`listener_app/sidebar_shared.py:82`、`listener_app/sidebar_translate_runtime.py:122`、`listener_app/sidebar_translate_runtime.py:130`、`listener_app/sidebar_translate_runtime.py:162`。
- `GET /api/config` 现在把 translate secret 暴露成顶层 `translate.deeplx_url` 状态对象；`PUT /api/config` 也只接受 `secret_updates.translate.deeplx_url`，并在写 TTS 时把活跃 provider 的路径回写到单一 `tts.config_path`：`listener_app/runtime_config_store.py:108`、`listener_app/runtime_config_store.py:116`、`listener_app/runtime_config_store.py:147`、`listener_app/runtime_config_store.py:190`、`listener_app/runtime_config_store.py:242`、`listener_app/runtime_config_store.py:262`、`listener_app/runtime_config_store.py:283`。
- 桌面壳 settings 能消费 `/api/config`，并且已经按 `windows_system` / `doubao` / `tencent_cloud` 渲染 TTS provider 分支；但当前首屏仍直接暴露 `speech_rate`、`loudness_rate`、`speed`、`volume`、`request_timeout_seconds` 这类次级调参：`desktop-shell/src/lib/api.ts:165`、`desktop-shell/src/components/shell/settings-workspace.tsx:413`、`desktop-shell/src/components/shell/settings-workspace.tsx:414`、`desktop-shell/src/components/shell/settings-workspace.tsx:434`、`desktop-shell/src/components/shell/settings-workspace.tsx:435`、`desktop-shell/src/components/shell/settings-workspace.tsx:442`。
- 当前文档已经把配置边界写死：前端只能通过 `GET /api/config` / `PUT /api/config` 读写，secret 只回元数据，shared 字段写回 `listener.json`，TTS provider 私有字段继续写回 provider 私有 JSON，runtime-only 的 `tts_auto_read` 不能反写持久化默认值：`config/listener.md:66`、`config/listener.md:70`、`config/listener.md:71`、`config/listener.md:73`、`config/listener.md:187`、`config/listener.md:205`、`docs/wechat-listening-pitfalls.md:533`、`docs/wechat-listening-pitfalls.md:537`、`docs/wechat-listening-pitfalls.md:539`、`docs/wechat-listening-pitfalls.md:542`。
- 当前活跃 OpenSpec change 已经把“完整安全 DTO”“按文件边界持久化”“settings 覆盖全部已支持 TTS providers”定义为现有能力；本需求应修改这些 capability 的 contract，而不是另起平行 capability：`openspec/changes/add-desktop-config-gui-and-apply-flow/proposal.md:8`、`openspec/changes/add-desktop-config-gui-and-apply-flow/proposal.md:9`、`openspec/changes/add-desktop-config-gui-and-apply-flow/specs/desktop-runtime-config-api/spec.md:3`、`openspec/changes/add-desktop-config-gui-and-apply-flow/specs/desktop-runtime-config-api/spec.md:14`、`openspec/changes/add-desktop-config-gui-and-apply-flow/specs/desktop-shell-settings/spec.md:3`、`openspec/changes/add-desktop-config-gui-and-apply-flow/specs/desktop-shell-settings/spec.md:14`。

## 改动边界
- Python 配置契约：`listener_app/runtime_config.py`、`listener_app/runtime_config_store.py`、`listener_app/sidebar_translate_runtime.py`、`listener_app/sidebar_shared.py`、`listener_app/sidebar_tts.py`。这里要改的是 schema、provider 解析、保存校验和兼容读取，不是 worker / health / 会话链路。
- 本地 API 与前端 DTO：`listener_app/runtime_api.py`、`desktop-shell/src/lib/api.ts`、`desktop-shell/src/hooks/use-desktop-settings.ts`、`desktop-shell/src/components/shell/settings-workspace.tsx`。这里要改的是 `/api/config` 读写形态和设置页字段层级，不是 `/api/runtime`、`/api/sessions` 或 WebSocket 事件。
- 文档与默认配置：`config/listener.json`、`config/listener.md`、`docs/wechat-listening-pitfalls.md`。任何 `listener.json` 字段语义变更都必须同步文档。
- OpenSpec 范围：优先修改既有 capability `desktop-runtime-config-api` 和 `desktop-shell-settings`；如需表达 translate provider 收敛或 TTS path map 迁移，应作为这两个 capability 的 delta，而不是新增一套无关 specs。

## 约束
- 兼容性：迁移期间必须可读旧 `translate.deeplx_url` / `translate.deeplx_url_env` 与旧 `tts.config_path`，避免现有源码态和 `%LOCALAPPDATA%` 运行时配置直接失效：`config/listener.md:102`、`docs/wechat-listening-pitfalls.md:489`。
- 安全性：`GET /api/config` 仍不得回显任何 secret 真值；`PUT /api/config` 仍只接受 write-only secret 更新，且不会顺手写 `.env.local`：`config/listener.md:70`、`docs/wechat-listening-pitfalls.md:534`、`docs/wechat-listening-pitfalls.md:539`、`docs/wechat-listening-pitfalls.md:540`。
- 一致性：shared 字段继续落 `listener.json`，provider 私有字段继续落 provider 私有 JSON，未知字段必须保留，写盘必须原子且使用 LF：`config/listener.md:71`、`config/listener.md:73`、`openspec/changes/add-desktop-config-gui-and-apply-flow/specs/desktop-runtime-config-api/spec.md:15`、`openspec/changes/add-desktop-config-gui-and-apply-flow/specs/desktop-runtime-config-api/spec.md:19`。
- 运行时语义：backend 仍然是启动时加载配置；`display.tts_auto_read_active_chat` 仍是持久化默认值，顶部朗读开关仍只改当前 runtime：`docs/wechat-listening-pitfalls.md:531`、`docs/wechat-listening-pitfalls.md:542`、`openspec/changes/add-desktop-config-gui-and-apply-flow/specs/desktop-shell-settings/spec.md:29`。
- 首启体验：fresh install 仍必须保持无需外部 DeepLX / 云 TTS 凭据即可进入壳和设置页，不能让 schema 收敛把安全默认值打回去：`README.md:41`、`README.md:49`、`docs/desktop-shell-build.md:17`。

## 验收标准
1. `GET /api/config` 返回的 translate 配置改为 provider-aware 结构，至少区分 shared 字段与 `translate.providers.<provider>`；DeepLX 与 `openai_compatible` 所需字段按 provider 分支暴露，secret 仍只返回 `configured/source/env_key` 元数据。
2. `PUT /api/config` 能按 provider-aware translate payload 与 `secret_updates.translate.<provider>` 保存配置；当 active provider 缺失必填字段或字段非法时，API 返回 field-level validation error，且磁盘文件保持不变。
3. `listener.json` 的 TTS 主配置改为 `tts.provider` + `tts.providers.<provider>.config_path` 结构；切换 provider 不会丢失未激活 provider 的路径配置，豆包/腾讯云私有字段仍只写各自 JSON。
4. 启动加载与保存链路在迁移期间同时兼容旧 `translate.deeplx_url(_env)` 和旧 `tts.config_path` 读取，但新保存结果只写新结构，避免长期双写。
5. 桌面壳 settings 首屏只保留 translate/TTS 的核心字段；`speech_rate`、`loudness_rate`、`speed`、`volume`、`request_timeout_seconds` 这类次级 TTS 调参必须移入高级区或从首阶段首屏移除。
6. `display.tts_auto_read_active_chat` 仍作为持久化默认值编辑，顶部 runtime `tts-auto-read` 开关继续独立工作，不因本次配置结构调整而混写。

## 验证方式
- 后端配置契约回归：`pytest tests/test_runtime_config.py tests/test_runtime_config_store.py tests/test_runtime_api.py`
- 前端设置页回归：`cd desktop-shell && npm test`
- 交付前构建回归：`cd desktop-shell && npm run build && cd src-tauri && cargo test`
- 高风险手工验证 1：用旧版 `config/listener.json` 与 provider 私有 JSON 启动 `python listener_app/backend_main.py --config ".\\config\\listener.json"`，确认旧配置仍可读。
- 高风险手工验证 2：通过设置页或 `PUT /api/config` 保存新结构后，检查 `GET /api/config` 不回显 secret 真值，且 `listener.json` / provider 私有 JSON 的未知字段未丢失。
- 高风险手工验证 3：在源码态与 Tauri 运行时各验证一次 provider 切换与“保存后需重启/托管 apply”提示，确认没有把 runtime-only toggle 当成持久化写回。
<!-- 下游：tasks.md 的验证步骤 -->

## 迁移 / 回滚 / 降级
- 迁移：首次落地必须提供旧结构读取兼容；新结构保存成功后，以新字段为准，不再继续新增对旧写法的扩展。
- 回滚：如果 provider-aware translate DTO 或 `tts.providers.<provider>.config_path` 写法导致设置页 / 保存链路不稳定，优先回退到当前已实现的 `/api/config` 契约与单一 `tts.config_path` 语义，同时保留已存在的 provider 私有 JSON 文件，不做 destructive 清理。
- 降级：若首阶段无法稳定承载全部 TTS 高级调参，允许仅保留核心 credential / endpoint / path 字段在首屏，其他高级字段延后或隐藏；不允许为了“看起来完整”继续把次级参数堆在主表单。
