# Plan: 桌面壳前端样式体系重构与信息层级优化

## 背景与动机
桌面壳已经是当前仓库唯一正式桌面 UI，且现有 OpenSpec 已把它定义成“会话列表 + 消息流”的主体验；继续在 runtime 或打包链上重复动刀，收益已经不如把前端表现层做正确。当前桌面壳能展示状态和消息，但页面结构、视觉 token 和状态表达仍停留在“开发页能看”的水平，导致健康状态、会话导航和消息阅读互相抢层级。
<!-- 下游：proposal.md 的 motivation -->

## Goal
- 在不改本地 HTTP / WebSocket 契约、不改 Python runtime 和 Tauri bootstrap 的前提下，把桌面壳重构为清晰的三层信息架构：运行总览、会话导航、消息阅读。
- 把当前深色模板式 token 升级成语义化视觉系统，并为 `loading`、`starting`、`ready`、`startup_failed`、`degraded`、`reconnecting`、未读、`preview_only`、`pending_translation` 提供一致且可区分的前端表达。
- 第一阶段只落一套正式主题，不引入双主题并行；默认视觉方向以更利于长时间阅读和状态分层的浅底运行台为准。
<!-- 下游：proposal.md 的 scope -->

## Non-goals
- 不修改 `listener_app/**`、`desktop-shell/src-tauri/**`、`desktop-shell/src/lib/api.ts` 的接口契约，也不改变 `/healthz`、`/api/runtime`、`/api/sessions`、`/events` 的语义。
- 不新增发送消息、设置页、provider 配置页、主题切换、A/B 视觉方案并行等新功能。
- 不为样式改造引入新的大型组件库迁移；继续基于当前 `React + Tailwind + class-variance-authority` 栈落地。
<!-- 下游：proposal.md 的 scope -->

## 当前仓库事实
- 桌面壳入口非常薄，`App.tsx` 只渲染 `DesktopShell`，没有额外路由层或页面壳；前端表现层重构的主落点就是桌面壳组件本身：`desktop-shell/src/App.tsx:1`。
- 当前 `desktop-shell.tsx` 同时定义了 header、会话列表和消息区，`SessionListPane`、`MessageStreamPane` 都内嵌在同一文件，且三块区域都依赖相似的圆角卡片和边框样式，信息权重没有明显层次：`desktop-shell/src/components/shell/desktop-shell.tsx:5`、`desktop-shell/src/components/shell/desktop-shell.tsx:62`、`desktop-shell/src/components/shell/desktop-shell.tsx:145`。
- 主题变量仍是以 `background/card/primary/accent` 为核心的深色配色桶，正文 UI 字体沿用 `Inter/Segoe UI/PingFang SC/Microsoft YaHei` 默认栈；当前还没有语义化到“画布/面板/状态/消息层级”这一层：`desktop-shell/src/index.css:3`、`desktop-shell/src/index.css:57`。
- `StatusBadge` 目前只有 `primary | neutral | accent` 三种 tone，`Button` 只有 `default | secondary | outline` 三种 variant，说明原子组件还不足以表达完整状态等级：`desktop-shell/src/components/ui/status-badge.tsx:5`、`desktop-shell/src/components/ui/button.tsx:6`。
- 前端数据层已经具备状态表达所需字段：`ShellConnectionState` 明确定义了 `loading`、`starting`、`ready`、`startup_failed`、`degraded`、`reconnecting`；`ShellSession` 已包含 `unread`、`updatedAt`、`previewOnly`；`ShellMessage` 已包含 `captureLevel`、`pendingTranslation`；`useDesktopShell` 负责从 HTTP snapshot 和 WebSocket 事件同步这些数据：`desktop-shell/src/lib/shell-types.ts:1`、`desktop-shell/src/lib/shell-types.ts:9`、`desktop-shell/src/lib/shell-types.ts:19`、`desktop-shell/src/hooks/use-desktop-shell.ts:108`、`desktop-shell/src/hooks/use-desktop-shell.ts:159`、`desktop-shell/src/hooks/use-desktop-shell.ts:234`。
- 连接状态语义已被前端测试固定：managed backend 冷启动应显示 `starting`，首次 fatal 应是 `startup_failed`，成功连接后故障才落 `degraded` / `reconnecting`；样式改造不能把这些状态重新混成一类：`desktop-shell/src/hooks/desktop-shell-connection.ts:11`、`desktop-shell/src/hooks/desktop-shell-connection.ts:18`、`desktop-shell/src/hooks/desktop-shell-connection.ts:25`、`desktop-shell/src/hooks/desktop-shell-connection.test.ts:25`。
- 已完成的 OpenSpec 变更把桌面壳定义成“会话列表 + 按会话消息流”的主 UI，并要求首屏经 HTTP hydrate、后续靠 WebSocket 保持同步，同时保留翻译展示与 TTS 语义；这次 change 必须建立在这个基线之上，而不是重新定义产品边界：`openspec/changes/refactor-wechat-auto-ui-frontend-split/specs/desktop-shell-ui/spec.md:1`。
- 项目文档已明确 `desktop-shell/` 是正式桌面 UI，回归命令至少包含 `npm test`、`npm run build`、`cargo test`，且 Tauri 壳保持 single-instance；前端样式改造不能顺手破坏这些交付约束：`README.md:3`、`README.md:96`、`docs/desktop-shell-build.md:12`、`docs/desktop-shell-build.md:73`、`docs/desktop-shell-build.md:115`、`docs/wechat-listening-pitfalls.md:27`。

## 改动边界
- 主要改动范围限定在 `desktop-shell/src/components/shell/**`、`desktop-shell/src/components/ui/status-badge.tsx`、`desktop-shell/src/components/ui/button.tsx`、`desktop-shell/src/index.css` 及其相关前端测试。
- 允许为桌面壳拆出新的表现层组件，例如运行总览、会话导航项、消息卡片、空态/错误态面板，但这些组件只消费现有 `useDesktopShell()` 暴露的数据，不重写状态机。
- OpenSpec 侧优先修改或补充 `desktop-shell-ui` 领域的 spec delta；除非发现视觉改造必须调整健康状态语义，否则不扩散到 `desktop-runtime-api`、`desktop-runtime-health`、打包相关 specs。
- 默认不触碰 `listener_app/**`、`desktop-shell/src-tauri/**`、`config/listener.json`；如果后续实现发现必须越界，应该在下游 proposal/design 阶段单独升级范围，而不是在这个 plan 里偷带。

## 约束
- 必须保留现有连接状态语义和命名，不能为了视觉统一把 `starting`、`startup_failed`、`degraded`、`reconnecting` 合并成模糊的“异常态”：`desktop-shell/src/lib/shell-types.ts:1`、`desktop-shell/src/hooks/desktop-shell-connection.ts:11`。
- 必须继续消费现有本地 `HTTP + WebSocket` 契约，不能引入直连 worker stdout、绕过 snapshot hydrate 或修改 `/healthz` 判活协议：`README.md:3`、`openspec/changes/refactor-wechat-auto-ui-frontend-split/specs/desktop-shell-ui/spec.md:10`、`docs/desktop-shell-build.md:117`。
- 必须保持 Tauri 壳 single-instance 与现有打包主路径不变；样式 change 不得引入 bootstrap、sidecar、运行时目录行为漂移：`docs/desktop-shell-build.md:14`、`docs/desktop-shell-build.md:16`、`docs/wechat-listening-pitfalls.md:29`。
- 当前仓库只维护一套正式桌面 UI，不允许为了视觉重构重新引回 Tk fallback 或平行旧界面：`README.md:9`、`docs/desktop-shell-build.md:10`。
- 若实现阶段改变了桌面壳对健康状态、监听状态或打包行为的对外表述，必须同步检查并更新 `docs/wechat-listening-pitfalls.md`，保持文档与行为一致：`docs/wechat-listening-pitfalls.md:1`。

## 验收标准
1. 页面层级完成重构：桌面壳在代码组织上拆分为运行总览、会话导航、消息阅读三类主要表现层组件，`desktop-shell.tsx` 不再同时承载所有主要 UI 结构和全部列表项/消息卡的细节渲染。
2. 基础样式完成语义化：`desktop-shell/src/index.css` 或等效样式入口提供覆盖画布、面板、文本层级、关键状态、选中会话、预览态消息的语义 token，组件不再只依赖 `background/card/primary/accent` 这类通用桶色。
3. 状态表达可区分：同一界面内，`loading`、`starting`、`ready`、`startup_failed`、`degraded`、`reconnecting` 六种连接状态都能通过 badge、摘要面板或状态栏被稳定区分，且不改变底层状态值。
4. 会话导航可扫读：选中态、未读数、最新预览、最近更新时间、`previewOnly`/会话类型等信息具备明确主次关系，列表不再表现为等权重的大块按钮墙。
5. 消息阅读优先级正确：消息正文或译文是第一视觉层，原始预览和元数据降为次级信息；`pendingTranslation=true` 与 `captureLevel=preview` 被表现成非错误但可感知的状态。
6. 空态与异常态明确：至少覆盖无会话、无消息、冷启动、启动失败、断线重连、降级运行这几类页面级状态，不再只靠零散小字提示。
7. 这次 change 不引入后端契约漂移；`desktop-shell` 现有回归命令可继续通过，且窄窗口下不出现主要内容溢出、遮挡或无法操作。

## 验证方式
- 自动化回归：`cd desktop-shell && npm test`、`cd desktop-shell && npm run build`、`cd desktop-shell/src-tauri && cargo test`。
- 手工验证：启动 `python listener_app/backend_main.py --config ".\\config\\listener.json"` 与 `cd desktop-shell && npm run dev`，确认运行总览、会话导航、消息阅读三层布局成立，且 HTTP hydrate + WebSocket 增量同步仍工作。
- 状态 walkthrough：至少覆盖 `ready`、`starting`、`startup_failed`、`degraded`、`reconnecting`、无会话、无消息、窄窗口宽度；对难以稳定手工复现的状态，需补前端测试或可控 fixture 证明渲染分支存在且可回归。
- 回归观察点：`/api/runtime`、`/api/sessions`、`/events` 仍保持原契约；前端不再误把冷启动显示成 `reconnecting`，也不因样式重构引入第二套桌面入口。

## 迁移 / 回滚 / 降级
- N/A：本 change 预期不涉及数据迁移、配置 schema 变更或打包目录迁移。
